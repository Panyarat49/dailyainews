### 1. Anthropic กล่าวหา Alibaba ลอบดูดความสามารถ Claude ผ่านบัญชีปลอม 25,000 บัญชี — [The Standard](https://thestandard.co/anthropic-alibaba-ai-theft-claude/)

Anthropic ส่งจดหมายถึงวุฒิสมาชิกสหรัฐฯ เมื่อวันที่ 10 มิถุนายนที่ผ่านมา กล่าวหาว่า **Alibaba** (ผ่านห้องปฏิบัติการ Qwen) อยู่เบื้องหลังปฏิบัติการใช้บัญชีปลอม **25,000 บัญชี** โต้ตอบกับ Claude รวม **28.8 ล้านครั้ง** ในช่วงปลายเดือนเมษายนถึงต้นมิถุนายน 2026 เป้าหมายคือความสามารถเฉพาะของ Claude ด้านวิศวกรรมซอฟต์แวร์ การให้เหตุผลเชิง agentic และการทำงานที่ซับซ้อนยาวนาน โดยใช้เทคนิค **distillation** — การดึงคำตอบจากโมเดลที่แข็งแกร่งกว่ามาฝึกโมเดลที่อ่อนแอกว่า — ในระดับที่ Anthropic ระบุว่าใหญ่ที่สุดเท่าที่บริษัทจีนเคยทำต่อ lab ชั้นนำในสหรัฐฯ ผลกระทบทันที: หุ้น Alibaba ในฮ่องกงร่วง **5%** แตะระดับต่ำสุดในรอบ 16 เดือน

กรณีนี้เป็น "IP war ยุคใหม่" ที่สนามรบคือ model weights และ interaction data ไม่ใช่โค้ดหรือสิทธิบัตร นักวิชาการชี้ว่าขอบเขตที่นับว่า distillation เป็นการขโมยเชิงพาณิชย์ยังไม่มีนิยามทางกฎหมายชัดเจน — ต้องนำเข้าชั้นเรียนเพื่อถก AI IP law และ international tech governance ผู้เชี่ยวชาญ AI มองว่าปฏิบัติการขนาด 28.8 ล้านครั้งแสดงว่านี่ไม่ใช่การทดลอง แต่เป็นการ systematically extract capabilities ที่มีมูลค่าสูงสุด ถ้าพิสูจน์ได้จะสร้างบรรทัดฐานใหม่สำหรับ ToS enforcement และบีบให้ AI labs ทุกรายเพิ่ม pattern-detection ใน API pipeline สำหรับโปรแกรมเมอร์: ตรวจสอบ ToS ของ AI API ที่ใช้งานในประเด็นห้าม distillation/model cloning — ขีดเส้นนี้กำลังถูก enforce จริง และ pattern ที่ Alibaba ใช้ (บัญชีปลอมจำนวนมาก + เป้าหมายเฉพาะ capability) เป็น reference สำหรับออกแบบ detection system ของตัวเอง

### 2. OpenAI เปิดตัว GPT-5.6 สามโมเดล Sol, Terra และ Luna — แต่เฉพาะ ~20 องค์กรที่รัฐบาลอนุมัติ — [The Verge](https://www.theverge.com/ai-artificial-intelligence/957845/openai-gpt-5-6-trump-administration-ai-preview)

หนึ่งวันหลังข่าว "ชะลอ" OpenAI เปิดตัว **GPT-5.6** อย่างเป็นทางการแบบ limited preview ประกอบด้วยสามโมเดล: **Sol** สำหรับงานยาก (coding, cybersecurity, biology, long-horizon agentic tasks), **Terra** สำหรับงานปริมาณสูง (customer support, internal tools, document analysis) และ **Luna** สำหรับงานประจำที่รวดเร็วและราคาถูก ราคา Sol อยู่ที่ **$5 input / $30 output ต่อล้าน token** — เกือบครึ่งราคาของ Claude Fable 5 ที่ $10/$50 ตาม The Verge อย่างไรก็ตาม โมเดลทั้งสามถูกจำกัดให้เฉพาะ **~20 องค์กร** ที่รัฐบาลสหรัฐฯ อนุมัติ ตาม executive order ของประธานาธิบดีทรัมป์วันที่ 2 มิถุนายน 2026 ซึ่งให้เวลา 30 วัน (ถึง 2 กรกฎาคม) ในการ benchmark ความปลอดภัย OpenAI ระบุว่า general release จะตามมา "ในสัปดาห์ข้างหน้า"

GPT-5.6 คือการ release โมเดลครั้งแรกที่ถูก gate อย่างเป็นทางการโดยกระบวนการรัฐบาล ไม่ใช่แค่ safety testing ของ lab เอง นักวิชาการชี้ว่านี่คือ precedent สำคัญ: รัฐอาจกำลังเดินหน้าสู่บทบาทคล้าย FDA สำหรับ AI frontier models ซึ่งถ้ากลายเป็น template ที่ประเทศอื่นนำไปใช้จะเปลี่ยน landscape AI governance ระดับโลก ผู้เชี่ยวชาญ AI มองว่าราคา Sol ที่ต่ำกว่า Fable 5 เกือบ 50% จะสร้างแรงกดดันด้านราคาในตลาด frontier models อย่างมีนัยสำคัญ โดยเฉพาะในช่วงที่ Anthropic เองก็อยู่ภายใต้ข้อจำกัดเดียวกัน สำหรับโปรแกรมเมอร์: เฝ้าดู July 2 อย่างใกล้ชิด — ถ้า approval process ยืดเยื้อเกินกว่านั้น API pricing ที่ถูกกว่าอาจยังเข้าไม่ถึงเป็นสัปดาห์หรือเป็นเดือน ควร benchmark use case ตัวเองกับ Sol pricing ก่อนตัดสินใจเปลี่ยน provider

### 3. บริษัท AI ทุกเจ้า—รวม Google—เรียกร้องให้กำกับดูแล AI ในแบบที่ตัวเองกำหนดเงื่อนไข — [The Register](https://www.theregister.com/ai-and-ml/2026/06/26/google-wants-ai-regulation-but-on-its-own-terms/5263276)

### 4. ช่องโหว่ร้ายแรง CVE-2026-12957 ใน Amazon Q: เปิด Git repo อันตราย → ขโมย cloud credentials — [The Register](https://www.theregister.com/cyber-crime/2026/06/26/amazon-q-flaw-let-booby-trapped-git-repos-execute-code-swipe-cloud-creds/5263202)

The Register รายงานช่องโหว่ความรุนแรงสูง **CVE-2026-12957** ใน **Amazon Q** ผู้ช่วยเขียนโค้ด AI ใน Visual Studio Code: การเปิด Git repository ที่ถูกสร้างขึ้นอย่างอันตรายบนเครื่องนักพัฒนาสามารถทำให้ผู้โจมตีรัน code บนเครื่องได้ และอาจดึง credentials ทั้งหมดที่เข้าถึง cloud environment ออกไป — รวมถึง API keys, database credentials และ cloud access tokens

ช่องโหว่ใน AI coding assistant ที่มีสิทธิ์กว้างนี้คือตัวอย่างของ "capability-security tradeoff" ที่ล้มเหลว — ยิ่ง AI tool ถูกออกแบบให้ทำงานได้กว้างเพื่อความสามารถ ยิ่งมี attack surface ใหญ่ขึ้น นักวิชาการชี้ว่า AI tools ที่ integrate ลึกกับ IDE ต้องผ่าน security model ที่เข้มงวดกว่า plugins ทั่วไป เพราะ credentials ที่ IDE เข้าถึงมักมีสิทธิ์ครอบคลุมทั้ง cloud account ผู้เชี่ยวชาญด้าน AI security มองว่า attack vector "open malicious repo → RCE → credential theft" มักถูก underestimate โดยนักพัฒนาที่ไว้วางใจ tooling จาก cloud provider รายใหญ่ สำหรับโปรแกรมเมอร์ที่ใช้ Amazon Q: **อัปเดต extension ทันทีและ rotate cloud credentials ที่อาจถูกเปิดเผย** — และ implement policy ตรวจสอบ repository จากภายนอกก่อนเปิดใน VS Code

### 5. งานวิจัย NUS: MRAgent ลด Token ลง 27 เท่า เทียบ LangMem ที่เผา 3.26 ล้าน Token ต่อ Query — [VentureBeat](https://venturebeat.com/orchestration/new-agentic-memory-framework-uses-118k-tokens-per-query-langmem-burns-through-3-26m)

นักวิจัยจาก **National University of Singapore** เพิ่งเผยแพร่ **MRAgent** framework สำหรับ agentic memory ที่แก้ปัญหาหลักของ long-horizon reasoning: context window เต็มเร็วและ retrieval pipeline ส่งคืนข้อมูลที่ไม่เกี่ยวข้อง แทนการใช้ "retrieve-then-reason" แบบ passive (ที่ไม่สามารถออก query ใหม่ระหว่าง reasoning) MRAgent ให้ agent พัฒนา memory แบบ dynamic โดยสะสมหลักฐาน (multi-step memory reconstruction) ที่ผสานกับกระบวนการ reasoning จริงๆ ผลลัพธ์: MRAgent ใช้ **118K tokens ต่อ query** เทียบกับ LangMem ที่ใช้ถึง **3.26 ล้าน tokens** — ประหยัดกว่า **27 เท่า**

งานนี้ตั้งคำถามพื้นฐานว่า memory ใน AI agent ควรทำงานอย่างไร นักวิชาการชี้ว่าการที่ agent ออก retrieval query ใหม่ระหว่าง reasoning ใกล้เคียงกับ metacognition มากกว่า passive lookup และเปิดพื้นที่วิจัยใหม่ที่ CS + cognitive science มาบรรจบกัน ผู้เชี่ยวชาญ AI มองว่า 27x token reduction ไม่ใช่ micro-optimization แต่เป็น architectural shift ที่อาจทำให้ long-horizon tasks ที่ไม่ practical ทางต้นทุนกลายเป็น viable จริง และจะเปลี่ยน cost structure ของ agentic AI อย่างมีนัยสำคัญถ้าพิสูจน์ใน production สำหรับโปรแกรมเมอร์ที่ build AI agents: ติดตาม GitHub และ paper ของ MRAgent เพื่อประเมิน integration กับ pipeline ของตัวเอง โดยเฉพาะถ้ามี tasks ที่ต้องรักษา context ยาวๆ หรือ multi-step reasoning ที่ cost สูง
