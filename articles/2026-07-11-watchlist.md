### 1. Apple (AAPL US · Tier 1) — Apple ฟ้อง OpenAI ฐานขโมยความลับทางการค้าด้านฮาร์ดแวร์ — [The Verge](https://www.theverge.com/tech/964350/apple-openai-lawsuit-trade-secrets)

Apple ยื่นฟ้อง OpenAI พร้อมกับ IO Products สตาร์ตอัปฮาร์ดแวร์ของ Jony Ive ที่ OpenAI ซื้อกิจการไปเมื่อปี 2025 โดยระบุชื่อจำเลยเพิ่มอีกสองคนคือ Tang Tan ประธานเจ้าหน้าที่ฝ่ายฮาร์ดแวร์ของ OpenAI และ Chang Liu อดีตวิศวกร Apple ที่ย้ายมาร่วมงานกับ OpenAI ตั้งแต่เดือนมกราคม คำฟ้องระบุว่า Apple ตรวจพบ "รูปแบบการขโมยความลับทางการค้า" อย่างเป็นระบบจากอดีตพนักงานที่เคยทำงานให้ Apple เพื่อนำไปต่อยอดแผนพัฒนาฮาร์ดแวร์ AI ของ OpenAI

คดีนี้เป็นบทเรียนคลาสสิกเรื่อง trade secret law ในวงการเทคโนโลยี — ความท้าทายทางกฎหมายคือการพิสูจน์ว่าอดีตพนักงานถ่ายโอน "ความรู้ที่เป็นกรรมสิทธิ์" จริง ต่างจากทักษะทั่วไปที่ติดตัวคนทำงานได้อย่างชอบธรรม การที่ OpenAI ดึงทีม Jony Ive บุกตลาดฮาร์ดแวร์ AI ทำให้ปะทะกับ Apple โดยตรงเป็นครั้งแรก ผลคดีอาจกำหนดทิศทางว่าใครจะเป็นผู้นำ form factor ถัดไปของอุปกรณ์ AI หลังยุคสมาร์ตโฟน ทีมที่ recruit จากบริษัทคู่แข่งในอุตสาหกรรม AI ควรทบทวนนโยบาย onboarding และ IP firewall ให้รัดกุมกว่าเดิม เพราะคดีลักษณะนี้อาจกระทบเงื่อนไขสัญญาจ้างงานและการเข้าถึงเอกสารภายในของพนักงานใหม่ทั้งวงการ

### 2. Meta Platforms (META US · Tier 1) — อัปเดตสำคัญ 2 รายการ

Meta ถอนฟีเจอร์ "Muse Image" บน Instagram ที่เพิ่งเปิดตัวไปเพียงไม่กี่วันก่อนหน้า ซึ่งอนุญาตให้ผู้ใช้ทั่วไปแท็กบัญชีสาธารณะใดก็ได้เพื่อสร้างภาพ AI จากคอนเทนต์ของบัญชีนั้น หลังเผชิญกระแสวิจารณ์ทันทีว่าเปิดช่องให้เกิดการสร้างภาพเลียนแบบบุคคลสาธารณะโดยไม่ได้รับความยินยอม กรณีนี้เป็นบทเรียนคลาสสิกเรื่อง product governance — การเปิดตัวฟีเจอร์ generative AI ที่กระทบสิทธิ์บุคคลสาธารณะโดยไม่มี consent framework รัดกุมพอ มักนำไปสู่การถอนฟีเจอร์อย่างรวดเร็วเมื่อเจอแรงต้านทางสังคม ทีมที่สร้างฟีเจอร์ลักษณะนี้ควรมี opt-in/consent check พร้อมใช้งานตั้งแต่วันเปิดตัว ไม่ใช่เพิ่มทีหลังหลังเกิดกระแส

**2.2 เครื่องมือตรวจจับภาพ AI ของ Meta เองพลาดตรวจจับภาพที่ถูกครอป — [CNA](https://www.channelnewsasia.com/business/meta-ai-image-detector-fails-identify-some-its-own-cropped-ai-images-reuters-analysis-finds-6246906)**

การวิเคราะห์ของ Reuters พบว่าเครื่องมือตรวจจับ AI-content ของ Meta ที่เปิดตัวคู่กับ Muse Image ไม่สามารถระบุภาพ AI ที่ Meta สร้างขึ้นเองได้บางส่วน หลังภาพเหล่านั้นถูกครอป ซึ่งเพิ่มความกังวลเรื่องการตรวจจับ deepfake ในช่วงก่อนการเลือกตั้งกลางเทอมสหรัฐฯ การที่เครื่องมือตรวจจับพลาดภาพที่ตนเองสร้างสะท้อนว่าการต่อสู้กับ deepfake ยังตามหลังความสามารถในการ generate ภาพอยู่มาก ทีมที่พึ่งพา AI-content detection เป็นแนวป้องกันควรมี defense-in-depth เพิ่มเติม เช่น provenance metadata แบบ C2PA แทนที่จะเชื่อ detector เดี่ยวตัวเดียว

กระทรวงพาณิชย์สหรัฐฯ ย้ายสหรัฐอาหรับเอมิเรตส์เข้าสู่กลุ่มประเทศที่ได้รับการยกเว้นใบอนุญาตส่งออกมากขึ้น ครอบคลุมทั้งชิป AI ของ Nvidia อุปกรณ์ทางการทหาร และดาวเทียมเชิงพาณิชย์ บริษัท G42 และ Core42 ของ UAE รวมถึงบริษัทสหรัฐฯ ที่ตั้งฐานปฏิบัติการในประเทศ จะไม่ต้องขอใบอนุญาตทุกครั้งสำหรับชิปและเซิร์ฟเวอร์ AI อีกต่อไป

### 5. Oracle (ORCL US · Tier 1) — Oracle เปิดตัว AI Agent Memory เวอร์ชัน 26.6 — [Oracle Blogs](https://blogs.oracle.com/database/oracle-ai-agent-memory-26-6)

Oracle อัปเดตบริการ AI Agent Memory ซึ่งฝังอยู่ใน Oracle AI Database เป็นเวอร์ชัน 26.6 เพิ่มความสามารถ hybrid search ที่ผสาน semantic search กับ keyword search เข้าด้วยกัน พร้อม full CRUD lifecycle control สำหรับ thread, memory, และ user profile รวมถึงการลบข้อมูลแบบ cascading Oracle ระบุผลทดสอบภายในว่าในบทสนทนา 80 เทิร์น ระบบ Agent Memory ชนะ 48 เทิร์นเทียบกับ flat history ที่ชนะเพียง 13 เทิร์น

การอัปเดตนี้สะท้อนว่า "หน่วยความจำ" ของ AI agent กำลังกลายเป็นองค์ประกอบสถาปัตยกรรมที่จริงจัง ไม่ใช่แค่ context window ธรรมดา การรัน memory layer อยู่ใน Oracle AI Database โดยตรงแทนที่จะกระจายข้าม operational DB, vector DB และ embedding provider แยกกัน ช่วยลด latency และความซับซ้อนของสถาปัตยกรรม แม้ตัวเลขชนะ 48 ต่อ 13 จะเป็นผลทดสอบภายในของ Oracle เองก็ตาม ทีมที่สร้าง enterprise AI agent บน Oracle stack ควรประเมิน hybrid search และ CRUD lifecycle control นี้เทียบกับโซลูชัน vector DB แยกต่างหากที่ใช้อยู่ เพื่อดูว่าลดความซับซ้อนของ pipeline ได้จริงหรือไม่
