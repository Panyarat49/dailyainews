### 1. บริษัท AI ล็อบบี้ให้ออสเตรเลียผ่อนคลายกฎหมายลิขสิทธิ์ ครีเอเตอร์ไม่พอใจ พรรครัฐบาลแตกความเห็น — [The Guardian](https://www.theguardian.com/technology/2026/jul/12/ai-australia-will-labor-water-down-copyright-laws-datacentres)

นักเขียน ศิลปิน และนักดนตรีชาวออสเตรเลียออกมาเคลื่อนไหวคัดค้าน หลังบริษัท AI ล็อบบี้ให้รัฐบาลผ่อนคลายกฎหมายลิขสิทธิ์เพื่อแลกกับการลงทุนสร้างดาต้าเซ็นเตอร์ในประเทศ นายกรัฐมนตรี Anthony Albanese เตรียมกล่าวสุนทรพจน์สำคัญด้าน AI ในสัปดาห์นี้ ขณะที่พรรค Labor เองยังมีความเห็นแตกแยกระหว่างฝ่ายที่อยากดึงดูดการลงทุนกับฝ่ายที่ต้องการปกป้องสิทธิ์ของครีเอเตอร์

กรณีนี้คือรูปแบบการต่อรองที่กำลังเกิดซ้ำในหลายประเทศ — บริษัท AI เสนอนำเงินลงทุนโครงสร้างพื้นฐานมาแลกกับสิทธิ์ใช้ข้อมูลฝึกโมเดลอย่างเสรีขึ้น ซึ่งอาจกลายเป็นบรรทัดฐานที่ตลาดอื่นอ้างอิงต่อไม่ว่าผลจะออกมาทางใด สำหรับทีมที่ฝึกหรือ fine-tune โมเดลด้วยข้อมูลจากออสเตรเลีย ควรจับตาการเปลี่ยนแปลงกฎหมายนี้อย่างใกล้ชิด เพราะอาจกระทบสิทธิ์การใช้ข้อมูลและ data-licensing pipeline ในอนาคตอันใกล้

### 2. นักวิจัยเตือนภัยคุกคามใหม่ "slopsquatting" ที่มากับ AI coding tool — [VentureBeat](https://venturebeat.com/security/forget-typosquatting-slopsquatting-is-the-software-supply-chain-threat-created-by-ai-coding-tools)

"Slopsquatting" คือรูปแบบโจมตี supply chain ใหม่ที่อาศัยการที่ AI coding assistant มัก hallucinate ชื่อแพ็กเกจโอเพนซอร์สที่ไม่มีอยู่จริงระหว่างช่วยเขียนโค้ด ผู้โจมตีจะจดทะเบียนชื่อแพ็กเกจปลอมเหล่านั้นแล้วฝังมัลแวร์ไว้ข้างใน เมื่อนักพัฒนาเชื่อคำแนะนำของ AI แล้วติดตั้งแพ็กเกจโดยไม่ตรวจสอบ มัลแวร์ก็จะเข้าไปอยู่ในโค้ดเบสทันที ชื่อนี้ผสมคำว่า "AI slop" กับ "typosquatting" ซึ่งเป็นเทคนิคหลอกลวงแบบเดิมที่จดโดเมนสะกดผิดเลียนแบบเว็บดัง

เคสนี้สะท้อนขีดจำกัดพื้นฐานของ LLM ที่ยัง hallucinate ชื่อ package ที่ไม่มีอยู่จริงได้บ่อย และพิสูจน์ว่าความเสี่ยงจาก AI ไม่ได้จบแค่ "คำตอบผิด" แต่ลามไปเป็นช่องโหว่ความปลอดภัยจริงในระบบซอฟต์แวร์ การแก้ที่ต้นเหตุต้องอาศัยทั้งการ grounding กับ package registry จริงระหว่าง inference และการปรับปรุง training data ไม่ใช่แค่ patch ที่ปลายทาง ทีมที่ใช้ AI coding assistant ควรเพิ่มขั้นตอนตรวจสอบชื่อแพ็กเกจกับ registry ทางการก่อน install ทุกครั้ง และห้าม auto-install จาก suggestion โดยไม่ผ่านการรีวิวมนุษย์ โดยเฉพาะใน CI/CD pipeline

### 3. OpenAI ขยาย ChatGPT เข้าสู่ครอบครัวและผู้สูงอายุ — [TechCrunch](https://techcrunch.com/2026/07/11/openai-bets-on-families-as-chatgpt-goes-deeper-into-households/)

OpenAI เปิดรับสมัครตำแหน่ง product manager ประจำซานฟรานซิสโก เพื่อสร้างประสบการณ์ ChatGPT สำหรับครอบครัว ผู้ดูแล และผู้สูงอายุโดยเฉพาะ ข้อมูลจาก Sensor Tower ที่ TechCrunch อ้างอิงระบุว่าสัดส่วนผู้ใช้ ChatGPT อายุ 35 ปีขึ้นไปทั่วโลกเพิ่มเป็น 31% ในไตรมาส 2 จาก 26% เมื่อปีก่อน ขณะที่สัดส่วนผู้ใช้อายุ 18-24 ปีลดลงจาก 34% เหลือ 29% ในสหรัฐฯ ผู้ปกครองที่ใช้สมาร์ตโฟนเกือบ 1 ใน 4 ใช้ ChatGPT ในไตรมาสนี้ เพิ่มจาก 16% เมื่อปีก่อน

การขยายฐานผู้ใช้จาก individual productivity ไปสู่ household เป็นทิศทางที่แพลตฟอร์มเทคโนโลยีใหญ่อย่าง Google, Apple และ Meta เคยเดินตามมาก่อน ข้อมูลนี้สะท้อนว่า ChatGPT กำลังเปลี่ยนจาก early-adopter tool เป็น mainstream utility ซึ่งการออกแบบสำหรับ caregiver และผู้สูงวัยต้องคำนึงถึง safety guardrail ที่ต่างจากฐาน power-user เดิม ทีมที่สร้างผลิตภัณฑ์บน ChatGPT API ควรเตรียมรับมือกับผู้ใช้ที่หลากหลายขึ้น ซึ่งต้องการ UX ที่เรียบง่ายกว่าและ error handling ที่ชัดเจนกว่าเดิม
