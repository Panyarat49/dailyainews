### 2. Oracle เพิ่ม Google Gemini เข้า AI Agent Studio — [The Register](https://www.theregister.com/ai-and-ml/2026/07/30/oracle-adds-google-gemini-to-the-agent-menu/5281331)

Oracle เตรียมเพิ่มโมเดล Gemini ของ Google เข้าสู่ AI Agent Studio สำหรับ Fusion Applications ขยายความร่วมมือกับ Google Cloud และให้ลูกค้ามีตัวเลือกเพิ่มในการสร้าง AI agent โดย Gemini 3.1 Flash Lite และ 3.5 Flash จะพร้อมใช้งานควบคู่กับโมเดลเดิมของ Oracle รวมถึงถูกฝังในเวิร์กโฟลว์ของ Oracle Fusion Applications และ NetSuite ผู้บริหาร Google Cloud ระบุว่าความร่วมมือนี้ออกแบบมาเพื่อให้องค์กรใช้ Gemini ในแอปพลิเคชันและ agentic workflow ได้ง่ายขึ้น

ดีลนี้สะท้อน multi-vendor strategy ขององค์กรซอฟต์แวร์ระดับ enterprise ที่เลือกไม่ผูกติดกับผู้ให้บริการโมเดลรายเดียว เพื่อรักษาอำนาจต่อรองและกระจายความเสี่ยงด้าน supply chain ของ AI การที่ Oracle มองโมเดลเป็นส่วนประกอบที่สลับได้มากกว่าจะผูกกับค่ายใดค่ายหนึ่ง กดดันให้ผู้พัฒนาโมเดลแข่งกันที่ราคาและความสามารถ multimodal สำหรับทีมที่พัฒนาบน Oracle Fusion หรือ NetSuite นี่คือโอกาสทดสอบ Gemini เทียบกับโมเดลเดิมในงาน agent จริงโดยไม่ต้องย้ายแพลตฟอร์ม แต่ควรวางแผน prompt และ tooling ให้ portable ข้ามโมเดลไว้ล่วงหน้า

### 3. หน่วยความจำแบบ storage ดันความจุ GPU สู่ระดับ TB — [The Register](https://www.theregister.com/storage/2026/07/30/gpus-could-explode-to-multiple-tb-with-new-storage-inspired-memory-tech/5281363)

Sandisk และ SK Hynix กำลังพัฒนาเทคโนโลยี High-Bandwidth Flash (HBF) ที่ใช้สถาปัตยกรรมคล้าย HBM แต่ใช้ NAND flash แทน DRAM เพื่อดันความจุหน่วยความจำของ GPU/AI accelerator จากหลักร้อย GB ไปสู่ระดับ TB โดย HBF รุ่นแรกของ Sandisk อ้างว่าทำ read bandwidth ได้ถึง 1.6TB/s เร็วกว่า HBM3e เล็กน้อยแต่ยังช้ากว่า HBM4 ที่ทำได้ 2.5TB/s ต่อสแตก ส่วนรุ่นถัดไปตั้งเป้าไปถึง 3.2TB/s

จุดขายหลักของ HBF ไม่ใช่ความเร็วแต่คือความจุระดับ TB ที่ HBM ทำไม่ได้ในราคาที่จับต้องได้ ซึ่งจะช่วยให้รันโมเดลขนาดใหญ่บน GPU น้อยตัวลงโดยไม่ต้อง shard ข้ามเครื่องมากเกินจำเป็น เป็นตัวอย่างที่ดีของการยืมสถาปัตยกรรม storage มาแก้ปัญหาคอขวดหน่วยความจำ AI ยังเป็นเทคโนโลยีช่วงต้นที่ทีม infrastructure ยังไม่ต้องวางแผนรอบนี้ แต่ทีมที่ทำ inference โมเดลใหญ่ควรจับตาไว้ เพราะถ้า HBF ไปถึงมือ cloud provider จริง จะเปลี่ยนสมการต้นทุนต่อ token ของโมเดลขนาดใหญ่ได้มาก

### 4. Gemini Robotics 2 ควบคุมหุ่นยนต์ได้ทั้งตัว — [The Verge](https://www.theverge.com/tech/973276/google-deepmind-gemini-robotics-2-whole-body)

Google DeepMind เปิดตัว Gemini Robotics 2 โมเดล AI ที่ควบคุมหุ่นยนต์ humanoid ได้ "ทั้งตัว" ตั้งแต่เท้าถึงปลายนิ้ว ต่างจากรุ่นก่อนที่เน้นควบคุมแค่ครึ่งบน โมเดลใหม่ทำให้หุ่นยนต์เดิน ย่อตัว ยืดตัว และหยิบจับสิ่งของได้ในโมเดลเดียว วิดีโอสาธิตที่ Google เผยแพร่แสดงให้เห็นหุ่นยนต์ Apollo 2 ของ Apptronik ก้มหยิบบัวรดน้ำและหยิบของเฉพาะจากชั้นวาง

การก้าวจากควบคุมแค่ครึ่งบนไปสู่ whole-body control เป็นตัวอย่างชัดเจนของโมเดลภาษา-การมองเห็น-การเคลื่อนไหว (VLA) ที่เริ่มเข้าใกล้การทำงานในโลกจริงมากขึ้น ลดความจำเป็นต้องแยกโมเดลควบคุม locomotion กับ manipulation ออกจากกัน ทำให้การประสานงานทั้งตัวเป็นธรรมชาติกว่าเดิม สำหรับทีมที่ทำงานด้าน robotics หรือ simulation ควรติดตาม API/SDK ที่ Google จะปล่อยตามมา เพราะโมเดลแบบนี้มีแนวโน้มลดงาน integration เดิมที่ต้องเขียน controller แยกส่วนสำหรับแต่ละ subsystem ของหุ่นยนต์
